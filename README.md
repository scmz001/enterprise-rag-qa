# 星辰科技企业制度问答系统

一个基于 RAG（检索增强生成）的企业制度问答应用。用自然语言提问，系统只依据 `data/docs/`
目录下的星辰科技官方文档作答，每条回答下方标注引用来源；文档里查不到的内容会明确回答
"无法确认"，不编造制度。

技术栈：

- 前端：Streamlit
- 编排：LangChain
- 向量库：ChromaDB，本地文件持久化，不需要单独启动服务
- 大模型：LM Studio 本地部署，走 OpenAI 兼容接口，数据不出本机

## 快速开始

```bash
# 0. 打开 LM Studio，加载一个对话模型和一个向量模型，启动 Local Server
#    默认地址 http://localhost:1234/v1
#    本项目实测使用 qwen3.5-9b + text-embedding-bge-m3

# 1. 创建虚拟环境并安装依赖（需 Python 3.10+，实测 3.14 可用）
py -3.14 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
#    国内网络建议追加清华镜像：-i https://pypi.tuna.tsinghua.edu.cn/simple

# 2. 把 .env.example 复制为 .env，填入 LM Studio 中实际的模型名
cp .env.example .env
#    不确定模型叫什么，执行：curl http://localhost:1234/v1/models

# 3. 把 data/docs/ 里的文档灌进知识库（首次必须执行，约 1 分钟）
.venv\Scripts\python.exe -m src.ingest

# 4. 启动问答界面
.venv\Scripts\streamlit run app.py
```

浏览器打开 <http://localhost:8501> 即可提问。不需要 Docker、Redis、PostgreSQL，也不需要
单独启动数据库服务。换一台电脑重复这四步即可，`data/docs/` 里的文档随仓库一起拉取，
向量库会自动重建。

本项目在本机 Python 3.14.4 上开发，全部依赖均已实测可安装、可导入。LM Studio 侧只需要
加载一个对话模型和一个 embedding 模型，再启动 Local Server。

## 二、依赖库说明

| 库 | 作用 |
| --- | --- |
| `streamlit` | 网页界面与对话控件 |
| `langchain` | RAG 编排框架 |
| `langchain-text-splitters` | 文档切分 |
| `langchain-openai` | 调用 OpenAI 兼容接口 |
| `langchain-chroma` | LangChain 与 ChromaDB 的桥接 |
| `chromadb` | 本地向量数据库 |
| `pypdf` | 解析 PDF |
| `python-dotenv` | 读取 `.env` 配置 |

`.md`、`.txt` 用 Python 标准库读取，`.docx` 也是标准库解析，docx 文件本质是 zip 包加 xml，
所以依赖清单里没有文档解析类的重型库。

## 三、使用方式

### 3.1 文档入库

先确认 LM Studio 已加载向量模型并启动了 Local Server，然后：

```bash
# 正式入库：解析 → 切分 → 向量化 → 写入 ChromaDB
.venv/Scripts/python.exe -m src.ingest

# 只看解析与切分结果，不连接模型，不需要 LM Studio
.venv/Scripts/python.exe -m src.ingest --dry-run

# 查看库里现有数据和内容抽样
.venv/Scripts/python.exe -m src.ingest --stats
```

默认全量重建，先清空再写入，避免重复入库；加 `--keep` 改为追加。

### 3.2 在终端里测试问答

不打开界面也能验证问答质量：

```bash
# 跑验收标准里的四个问题，推荐先跑这个
.venv/Scripts/python.exe -m src.rag_chain --demo

# 单次提问
.venv/Scripts/python.exe -m src.rag_chain "年假几天？"

# 交互式连续问答，输入 exit 退出
.venv/Scripts/python.exe -m src.rag_chain -i

# 只看检索到哪些片段，不调用对话模型，排查答非所问时很有用
.venv/Scripts/python.exe -m src.rag_chain -r "年假几天？"
```

### 3.3 启动完整应用

```bash
# Windows 命令行 / PowerShell
.venv\Scripts\streamlit run app.py

# Git Bash
./.venv/Scripts/streamlit.exe run app.py
```

### 3.4 界面操作

- 侧边栏列出 `data/docs/` 下的全部文档，以及各自已入库的文本块数量，没有入库的会标出提示。
- 上传新文档支持 .md / .txt / .docx / .pdf。上传后点"保存并重建索引"，文件存进 `data/docs/`
  并自动重建整个索引，同名文件会被覆盖。
- 文档内容改动后点"重建索引"，会重新解析全部文档并重灌向量库。
- 每条回答下方可展开查看文件名、章节、页码、相关度距离和片段原文。
- "清空对话"只清空界面上的聊天记录，不影响知识库。

### 3.5 等待时间

`qwen3.5-9b` 是推理模型，会先内部思考再输出。这段时间模型一个字都不返回，界面用持续跳秒的
状态条表示还在工作，第一段文字到达后切换为逐字流式显示。实测耗时：

- 具体事实型问题（"年假几天？"）：约 11~13 秒
- 整份文档概述型问题（"差旅与报销制度是什么？"）：约 25 秒

概述型问题要综合多个片段，思考更久。输出额度由 `config.LLM_MAX_TOKENS`（当前 4096）控制，
它必须同时容纳思考和回答两段。额度是上限而非目标，调大不会拖慢简单问题；哪天仍出现
"输出额度耗尽"的报错，把这个值调大即可。

## 四、纯标题块问题

PDF 和 DOCX 的第 1 块曾经是"文档标题 + (2026版) 副标题"，没有正文。原先记为"约 7 个"，
2026-10-05 用 `scripts/check_title_only.py` 从向量库逐块清点后确认为 6 个：

| 来源 | 块编号 | 长度 | 内容 |
| --- | --- | --- | --- |
| 项目管理制度.docx | 项目管理制度-000 | 28 字 | 星辰科技项目管理制度 星辰科技项目管理制度(2026版) |
| 差旅与报销制度.docx | 差旅与报销制度-000 | 30 字 | 星辰科技差旅与报销制度 星辰科技差旅与报销制度(2026版) |
| 财务发票管理制度.docx | 财务发票管理制度-000 | 32 字 | 星辰科技财务发票管理制度 星辰科技财务发票管理制度(2026版) |
| 招聘与面试流程.pdf | 招聘与面试流程-000 | 34 字 | 星辰科技招聘与面试流程规范 星辰科技招聘与面试流程规范(2026版) |
| 客户服务与数据安全.pdf | 客户服务与数据安全-000 | 38 字 | 星辰科技客户服务与数据安全政策 星辰科技客户服务与数据安全政策(2026版) |
| IT运维与故障响应规范.pdf | IT运维与故障响应规范-000 | 42 字 | 星辰科技 IT 运维与故障响应规范 星辰科技 IT 运维与故障响应规范(2026版) |

六个块全部是对应文件的第 1 块，编号都以 `-000` 结尾，内容只有文档标题和版本副标题。
5 个 `.md` 与 3 个 `.txt` 不产生这类块，它们的一级标题后面紧跟着二级标题，中间没有正文，
切分器不会为它单独生成文本块。

这些块会被误召回，并且已经造成了实际损害。早期用"年假几天？"这类问具体事实的问题测试时，
6 个块一次都没被召回，一度以为没有影响；换成问整份文档的问法后结论完全相反，因为标题块
本身就是文档标题，字面匹配度最高。用 `scripts/check_inducement_recall.py` 实测，5 个问题
各取 Top-5，共 25 个名额：

| 提问 | 命中标题块 | 排名 | 距离 |
| --- | --- | --- | --- |
| 差旅与报销制度是什么？ | 1 个 | 第 1 名 | 0.3783 |
| 财务发票管理制度讲了什么？ | 1 个 | 第 1 名 | 0.3827 |
| 员工手册的主要内容是什么？ | 0 | — | — |
| 信息安全管理制度有哪些要求？ | 0 | — | — |
| 项目管理制度是怎么规定的？ | 0 | — | — |

端到端问答时，模型真的把纯标题块当成了来源引用：

```
* 制度名称：星辰科技财务发票管理制度(2026 版) [1]
```

用户点开来源 `[1]` 看不到任何正文，引用支撑不了结论。`TOP_K=4` 时它还会占掉 4 个名额中的 1 个。

2026-10-05 已在入库阶段把这类块过滤掉。`config.MIN_PREAMBLE_CHARS = 60`：文档首个章节标题
之前的前置块，清理掉标题标记后实质内容不足 60 字，就当作只有标题、没有信息量，切分时直接
丢弃。判定依据是位置加长度，不针对具体文件，换一批文档同样适用；只对前置块生效，不会误伤
内容较短的正常条款。

- 效果：文本块 72 降到 66，6 个目标块各减 1，其余文件的块数不变
- 复验：同一组诱导性查询，25 个 Top-5 名额中标题块召回 0 次，"差旅与报销制度是什么？"的
  Top-1 由标题块变为 `第一章 差旅住宿标准`
- 复核方式：`.venv/Scripts/python.exe scripts/check_title_only.py`（预期 0 个）和
  `.venv/Scripts/python.exe scripts/check_inducement_recall.py`

## 五、三层防编造机制

1. 检索前预过滤。最相关的片段距离仍超过 `SCORE_THRESHOLD`（0.55）时直接返回固定话术，
   连模型都不调用。实测文档内问题距离 0.31~0.38，文档外提问 0.49~0.63，阈值取在断层中间。
2. 提示词约束。要求模型只能依据资料作答，每条结论必须标 `[编号]`，资料不足时原样回复
   固定话术，数字必须与原文完全一致。
3. 生成后检查。模型若表达"查不到"，统一替换成标准话术，保证口径一致；回答里没有任何
   来源编号时，界面提示"未标注来源"以便人工核对。

模型输出为空时，界面显示的是生成失败的报错和重试提示，提示里明确说明这不代表公司制度中
没有相关规定。

## 六、验收标准核对

| 验收标准 | 结果 | 验证方式 |
| --- | --- | --- |
| `streamlit run app.py` 能启动 | 通过 | 实际启动服务器，HTTP 200、无报错 |
| 提问"年假几天？"基于《员工手册.md》回答 | 通过 | 答 5/10/15/20 天，来源 `员工手册.md ｜ 二、年假制度` |

| 问文档中不存在的问题，系统能说"无法确认" | 通过 | 回固定话术，且区分于"生成失败"的报错 |
