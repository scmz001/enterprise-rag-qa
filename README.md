# 星辰科技企业制度问答系统

一个基于 **RAG（检索增强生成）** 的企业制度问答应用：用自然语言提问，系统只依据 `data/docs/`
目录下的星辰科技官方文档作答，并在每条回答下标注引用来源；文档里查不到的内容，系统会明确回答
"无法确认"，绝不编造制度。

- 前端：Streamlit（单页应用，无需前后端分离）
- 编排：LangChain
- 向量库：ChromaDB（本地文件持久化，不需要单独启动服务）
- 大模型：LM Studio 本地部署模型（通过 OpenAI 兼容接口调用，数据不出本机）

---

## 🚀 快速开始

```bash
# 0. 前置：打开 LM Studio，加载一个「对话模型」和一个「向量模型」，启动 Local Server
#    默认地址 http://localhost:1234/v1
#    （本项目实测使用 qwen3.5-9b + text-embedding-bge-m3）

# 1. 创建虚拟环境并安装依赖（需 Python 3.10+，实测 3.14 可用）
py -3.14 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
#    国内网络建议追加清华镜像：-i https://pypi.tuna.tsinghua.edu.cn/simple

# 2. 配置模型名：把 .env.example 复制为 .env，填入 LM Studio 中实际的模型名
cp .env.example .env
#    不确定模型叫什么？执行：curl http://localhost:1234/v1/models

# 3. 把 data/docs/ 里的文档灌进知识库（首次必须执行，约 1 分钟）
.venv\Scripts\python.exe -m src.ingest

# 4. 启动问答界面
.venv\Scripts\streamlit run app.py
```

浏览器会自动打开 <http://localhost:8501>，在输入框里提问即可。

**不需要** Docker、Redis、PostgreSQL，也不需要单独启动任何数据库服务。
换一台电脑只需重复上面 4 步——文档已在仓库里，向量库会自动重建。

## 二、依赖库说明（每个库的作用）

`requirements.txt` 中只包含运行本项目的必要库，逐条说明如下：

| 库 | 作用（一句话） |
| --- | --- |
| `streamlit` | 把 Python 脚本直接变成网页界面，提供对话窗口、侧边栏和文件上传控件。 |
| `langchain` | RAG 编排框架，负责把"文档处理 → 检索 → 提示词组装 → 调用模型"串成一条流水线。 |
| `langchain-text-splitters` | 文档切分器，把长文档按标题层级切成大小合适、语义完整的文本块。 |
| `langchain-openai` | OpenAI 接口的 LangChain 客户端，用它连 LM Studio 的本地模型服务。 |
| `langchain-chroma` | LangChain 与 ChromaDB 之间的桥接层，让向量库能直接参与链路编排。 |
| `chromadb` | 本地文件型向量数据库，负责存储和按语义相似度找回相关段落。 |
| `pypdf` | 解析 .pdf 文件，提取其中的文字内容。 |
| `python-dotenv` | 从 `.env` 文件读取配置和密钥，避免把敏感信息写死在代码里。 |

`.md`、`.txt` 由 Python 标准库直接读取；`.docx` 也是标准库解析（docx 文件本质是
zip 包加 xml，无需第三方库）。因此依赖清单里没有文档解析类的重型库。

## 四、使用方式

### 4.1 把文档灌进知识库（第二步）

先确认 LM Studio 已加载好向量模型（默认 `bge-m3`）并启动了 Local Server，然后：

```bash
# 正式入库：解析 → 切分 → 向量化 → 写入 ChromaDB
.venv/Scripts/python.exe -m src.ingest

# 只看解析与切分结果，不连接模型（不需要 LM Studio）
.venv/Scripts/python.exe -m src.ingest --dry-run

# 查看库里现有数据和内容抽样
.venv/Scripts/python.exe -m src.ingest --stats
```

默认是**全量重建**（先清空再写入），避免重复入库；加 `--keep` 则改为追加。

### 4.2 在终端里测试问答效果（第三步）

不需要打开界面，直接用命令行验证问答质量：

```bash
# 跑验收标准的四个问题（推荐先跑这个）
.venv/Scripts/python.exe -m src.rag_chain --demo

# 单次提问
.venv/Scripts/python.exe -m src.rag_chain "年假几天？"

# 交互式连续问答，输入 exit 退出
.venv/Scripts/python.exe -m src.rag_chain -i

# 只看检索到了什么片段，不调用对话模型（排查"答非所问"时很有用）
.venv/Scripts/python.exe -m src.rag_chain -r "年假几天？"
```

注意：`qwen3.5-9b` 是推理模型，会先思考再回答，**每次约 10~15 秒**属正常。

### 4.3 启动完整应用

```bash
# Windows 命令行 / PowerShell
.venv\Scripts\streamlit run app.py

# Git Bash
./.venv/Scripts/streamlit.exe run app.py
```

浏览器会自动打开 `http://localhost:8501`，在输入框里提问即可。

**使用说明**

- **侧边栏**：列出 `data/docs/` 下的全部文档及各自已入库的文本块数量（✅ 已入库 / ⚠️ 尚未入库）。
- **上传新文档**：支持 .md / .txt / .docx / .pdf，上传后点「保存并重建索引」，
  文件会存进 `data/docs/` 并自动重建整个索引（同名文件会被覆盖）。
- **重建索引**：文档内容改动后点它，会重新解析全部文档并重灌向量库。
- **引用来源**：每条回答下方可展开查看文件名、章节、页码（PDF）、相关度距离和片段原文。
- **清空对话**：只清空界面上的聊天记录，不影响知识库。

**关于等待时间**：`qwen3.5-9b` 是推理模型，会先内部思考再输出。
这段时间模型一个字都不返回，所以界面用**持续跳秒的状态条**表示"还在工作"，
第一段文字到达后切换为逐字流式显示。实测耗时：

- 具体事实型问题（"年假几天？"）：约 **11~13 秒**
- 整份文档概述型问题（"差旅与报销制度是什么？"）：约 **25 秒**（要综合多个片段，思考更久）

输出额度由 `config.LLM_MAX_TOKENS`（当前 4096）控制，它必须同时容纳"思考 + 回答"两段。
额度是上限而非目标，调大不会拖慢简单问题。若某天仍出现"输出额度耗尽"的报错，调大该值即可。

**问题**：PDF 和 DOCX 的第 1 块是纯标题块，经实际清点为 **6 个**（原记为"约 7 个"，
2026-10-05 用 `scripts/check_title_only.py` 从向量库逐块清点后修正）：

| 招聘与面试流程.pdf | 招聘与面试流程-000 | 34 字 | 星辰科技招聘与面试流程规范 星辰科技招聘与面试流程规范(2026版) |
| 客户服务与数据安全.pdf | 客户服务与数据安全-000 | 38 字 | 星辰科技客户服务与数据安全政策 星辰科技客户服务与数据安全政策(2026版) |
| IT运维与故障响应规范.pdf | IT运维与故障响应规范-000 | 42 字 | 星辰科技 IT 运维与故障响应规范 星辰科技 IT 运维与故障响应规范(2026版) |

全部为对应文件的第 1 块（编号均以 `-000` 结尾），只有"文档标题 + (2026版) 副标题"，
没有正文。5 个 `.md` 与 3 个 `.txt` 不产生这类块——它们的一级标题后面紧跟着二级标题，
中间没有正文，切分器不会为它单独生成文本块。

**验证结论：会被误召回，且已造成实际损害**

早期用"年假几天？"这类**问具体事实**的问题测试时，这 6 个块一次都没被召回，一度以为无影响。
但换成**问整份文档**的问法后结论完全相反——因为标题块本身就是文档标题，字面匹配度最高。
用 `scripts/check_inducement_recall.py` 实测（5 个问题 × Top-5 = 25 个名额）：

| 提问 | 命中标题块 | 排名 | 距离 |
| --- | --- | --- | --- |
| 差旅与报销制度是什么？ | 1 个 | **第 1 名** | 0.3783 |
| 财务发票管理制度讲了什么？ | 1 个 | **第 1 名** | 0.3827 |
| 员工手册的主要内容是什么？ | 0 | — | — |
| 信息安全管理制度有哪些要求？ | 0 | — | — |
| 项目管理制度是怎么规定的？ | 0 | — | — |

危害的硬证据：端到端问答时模型真的把纯标题块当成了来源引用——
`* 制度名称：星辰科技财务发票管理制度(2026 版) [1]`，
用户点开来源 `[1]` 却看不到任何正文，**引用无法支撑结论**。
且 `TOP_K=4` 时它会占掉 4 个名额中的 1 个，稀释参考资料。

**处置：已在入库阶段过滤（2026-10-05）**

`config.MIN_PREAMBLE_CHARS = 60`：文档首个章节标题之前的"前置块"，
若清理掉标题标记后实质内容不足 60 字，视为只有标题、没有信息量，切分时直接丢弃。
判定依据是**位置 + 长度**，不针对具体文件，换一批文档同样适用；
只对"前置块"生效，不会误伤内容较短的正常条款。

- 效果：文本块 **72 → 66**，6 个目标块各减 1，其余文件块数不变（无误伤）
- 复验：同一组诱导性查询，25 个 Top-5 名额中标题块召回 **0 次**；
  "差旅与报销制度是什么？"的 Top-1 由标题块变为 `第一章 差旅住宿标准`
- 复核方式：`.venv/Scripts/python.exe scripts/check_title_only.py`（预期 0 个）
  ＋ `.venv/Scripts/python.exe scripts/check_inducement_recall.py`

## 七、三层防编造机制（第三步实现）

回答的可靠性由三层依次保证，任何一层都不允许"编造制度"：

1. **检索前预过滤**：最相关的片段距离仍超过 `SCORE_THRESHOLD`（0.55）时，
   直接返回固定话术，连模型都不调用。实测文档内问题距离 0.31~0.38、文档外提问
   0.49~0.63，阈值取在断层中间，不会误伤文档内问题。
2. **提示词约束**：明确要求模型只能依据资料作答、每条结论必须标 `[编号]`、
   资料不足时必须原样回复固定话术、数字必须与原文完全一致。
3. **生成后检查**：模型若表达"查不到"，统一替换成标准话术，保证口径一致；
   若回答里没有任何来源编号，界面会提示"未标注来源"以便人工核对。

**特别注意**：模型输出为空**不等于**"制度里没有"。空输出会显示专门的报错提示，
明确告知"不代表公司制度中没有相关规定"，避免把服务故障误报成制度缺失。
